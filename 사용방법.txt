진료 카운터 v13 — 업무 카운터 + 대기 관리 + 데스크 호출 (Windows)

■ 파일 (Python 설치 필요 없음)
- 데스크.exe : 데스크 PC 2대 모두 같은 파일
- 진료실.exe : 진료실 PC 2대 모두 같은 파일 (설정에서 진료실 1/2 선택)
  바탕화면 등 원하는 곳에 복사해서 더블클릭하면 됩니다.
  처음 실행 시 'Windows의 PC 보호' 파란 창이 뜨면 '추가 정보' → '실행'을 누르세요.
  (서명되지 않은 자체 제작 프로그램이라 뜨는 경고입니다)
  매일 자동 실행하려면 Win+R → shell:startup 입력 → 열린 폴더에 exe 바로가기를 넣으세요.
서버 PC가 따로 없습니다. 모든 PC가 인터넷의 Firebase에 접속해 실시간으로 주고받으므로
어느 PC를 먼저 켜고 끄든 상관없고, IP 주소나 방화벽 설정도 필요 없습니다.

────────────────────────────────
[1] Firebase 준비 (처음 한 번, 약 10분)
────────────────────────────────
1. https://console.firebase.google.com 접속 → 기존 프로젝트 선택 (또는 새 프로젝트 추가)
2. 왼쪽 메뉴 '빌드(Build)' → 'Realtime Database' → '데이터베이스 만들기'
   - 위치: 싱가포르(asia-southeast1) 권장
   - 보안 규칙: '잠금 모드'로 시작
   ※ Firestore가 아니라 Realtime Database입니다. 기존 프로젝트에 Firestore를 쓰고 있어도
     Realtime Database를 추가로 만들면 되고, 기존 데이터에는 영향이 없습니다.
3. Realtime Database의 '규칙(Rules)' 탭에서 내용을 전부 지우고 아래를 붙여넣은 뒤 '게시'

{
  "rules": {
    ".read": false,
    ".write": false,
    "clinics": {
      "$code": {
        ".read": "$code.length >= 24",
        ".write": "$code.length >= 24"
      }
    }
  }
}

4. '데이터' 탭 맨 위의 주소를 복사해 둡니다.
   예) https://프로젝트이름-default-rtdb.asia-southeast1.firebasedatabase.app

────────────────────────────────
[2] PC 설정 (PC마다 처음 한 번)
────────────────────────────────
① 첫 번째 데스크 PC
  - 데스크.exe 실행 → ⚙ 설정
  - '이 데스크 이름'에 데스크 1 입력
  - '처음 설정 (새 연결 키 만들기)' → 위 4번 주소 붙여넣기 → 저장
  - 다시 ⚙ 설정 → '연결 키 복사' → 메신저나 메모로 나머지 PC에 전달
② 두 번째 데스크 PC
  - 데스크.exe 실행 → ⚙ 설정 → 이름 데스크 2, 연결 키 붙여넣기 → 저장
③ 진료실 PC 2대
  - 진료실.exe 실행 → ⚙ → 진료실 번호 선택, 연결 키 붙여넣기 → 저장
  - 이전 버전 기록이 있으면 '이전 버전(v12) 기록 서버로 올리기' 한 번 누르기
    (기존 기록 파일은 그대로 두고 복사만 합니다. 이전 업무 건수는 진료 완료 인원으로 함께 계산됩니다.
     자동으로 못 찾으면 이전 프로그램의 'JSON 백업' 파일을 직접 선택하면 됩니다)

처음 실행 시 Windows 방화벽 창이 뜨지 않습니다(바깥으로만 접속).
화면에 '● 실시간 연결됨' / '● 연결됨'이 보이면 완료입니다.

────────────────────────────────
[3] 매일 사용
────────────────────────────────
데스크
- 접수 시 해당 진료실 '＋ 대기 등록', 잘못 누르면 '− 등록 취소'
- '내가 받을 호출'에서 진료실 1 / 진료실 2 / 전체 담당 중 선택
  · 오전: 데스크 1 → 진료실 1, 데스크 2 → 진료실 2
  · 오후: 남는 직원이 자기 PC에서 '전체 담당'만 누르면 됨 (다른 데스크는 자동으로 해제)
  · 담당 데스크가 없거나 꺼져 있으면 켜져 있는 모든 데스크에 알림이 갑니다 (호출 누락 방지)
- 데스크가 꺼지거나 15초 넘게 연결이 없으면 담당이 없는 것으로 보고 켜진 모든 데스크에 알립니다.
- 인터넷이 끊기면 빨간 경고가 뜨고 숫자가 회색으로 바뀝니다. 끊긴 사이 3분 넘게 지난 호출은
  울리지 않고 '놓친 호출'로 표시됩니다.
- 한 데스크가 '확인'을 누르면 다른 데스크의 팝업도 함께 닫힙니다.
- 호출이 오면 소리 + 맨 앞 팝업. 환자를 들여보낸 뒤 '확인'을 누르면 그 진료실 대기가 1명 줄어듭니다.
  두 데스크가 동시에 눌러도 1명만 줄어듭니다.
- 알림음은 ⚙ 설정에서 진료실마다 다르게 고를 수 있습니다(미리 듣기, 반복 1~3회).
  기본: 진료실 1 = 딩동, 진료실 2 = 딩동(낮게), 직원 호출 = 삐삐삐
  딩동은 높게·낮게·아주 낮게·빠르게·느리게·두 번 등 여러 가지 중에서 고를 수 있습니다.
- 진료실 1·2가 좌우로 나란히 보이고, 대기 / 오늘 진료 완료 / 업무별 건수 / 마지막 호출 시각이 실시간 표시
- 업무 이름(예: 폐암사후)을 누르면 그 진료실의 오늘·이번 달·올해 인원, 마지막 기록 시각, 오늘 시각 목록이 나옵니다.
- 과장님께 알림: 진료실 칸의 [대기] [폐암사후] [종검결과] 버튼을 누르면 그 진료실 화면에
  '과장님, 폐암사후 상담 대기중입니다' 팝업과 소리가 뜹니다. 알림만 가고 숫자는 세지 않습니다.
  과장님이 확인하면 데스크에 '✔ 과장님 확인'이 표시됩니다. 버튼 이름은 ⚙ 설정에서 바꿀 수 있습니다.
- 📊 월별 통계: 달력 형식으로 날짜별 진료실 인원 표시, 날짜를 누르면 업무별 내역. CSV 내보내기도 가능

진료실
- 업무 카운터: + 버튼 클릭. 업무 + 한 번 = 진료 완료 1명으로 기록됩니다(카운팅만, 대기 인원은 그대로).
- − 버튼: 그 업무의 마지막 기록을 취소합니다.
- + 를 누르면 6초 동안 '↶ 되돌리기' 버튼이 떠서 바로 취소할 수 있습니다.
- 다음 환자 호출: 호출 버튼 클릭. 대기 0명이면 호출이 나가지 않습니다.
  호출만으로는 대기가 줄지 않고, 데스크에서 '확인'(환자 들여보냄)을 누를 때 대기 −1 됩니다.
- 데스크가 확인하기 전에는 버튼이 '🔁 다시 호출'로 바뀝니다. 못 들었을 때 여러 번 눌러도 대기는 그대로입니다.
- 데스크가 확인하면 진료실 화면에 '✔ 데스크 1 확인'이 표시됩니다.
- 잘못 불렀으면 '호출 취소'(5분 안) → 데스크 팝업이 닫히고, 이미 확인된 경우 대기도 +1로 되돌아갑니다.
- 🙋 직원 호출: 환자 호출과 별개로 직원을 진료실로 부릅니다(대기 인원 변화 없음). 그 진료실 담당 데스크에
  보라색 팝업과 다른 소리로 알리고, 데스크가 '확인(가는 중)'을 누르면 진료실에 '✔ 데스크 1 가는 중'이 뜹니다.
- '호출 받는 곳'에 지금 호출을 받는 데스크가 표시됩니다. 켜진 데스크가 없으면 빨간 경고가 뜹니다.
- 오늘 입력 시간 목록에서 선택 후 '선택 기록 삭제' 가능
- 데스크에서 보낸 알림('과장님, ~ 대기중입니다')은 맨 앞 팝업으로 뜨고, '확인'을 누르면 데스크에 표시됩니다.
  알림 소리는 ⚙ 설정에서 바꿀 수 있습니다.
- 📅 기록: 달력 형식 월별 기록 / CSV
- 업무 이름을 누르면 오늘·이번 달·올해 인원과 마지막 기록 시각이 나옵니다.
- 인터넷이 잠깐 끊겨도 업무·완료 기록은 PC에 보관했다가 연결되면 자동 전송됩니다(미전송 N건 표시).
  호출만은 연결된 상태에서만 됩니다.

[중요]
────────────────────────────────
- 환자 이름·생년월일 등 개인정보는 입력하는 곳이 없습니다. Firebase에는 진료실 번호, 대기 인원,
  업무 종류, 시각만 저장됩니다.
- 연결 키를 아는 사람은 이 데이터를 보고 수정할 수 있으니 원내 PC 외에는 공유하지 마세요.
- 설정은 각 PC의 %LOCALAPPDATA%\ClinicCounter13 에 저장되고 창 위치도 기억합니다.
- 날짜가 바뀌면 대기 인원은 0부터 새로 시작하고, 기록은 날짜별로 따로 쌓입니다.
- 병원 네트워크가 firebasedatabase.app 접속을 막으면 연결되지 않습니다. 이 경우 전산 담당자에게
  해당 주소 허용을 요청하세요.
